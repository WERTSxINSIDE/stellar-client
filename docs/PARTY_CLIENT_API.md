# Пати и метки — контракт для клиента

Сайт хранит состав пати и последние координаты участников. Клиент раз в 1–2 секунды
отправляет свою позицию и получает позиции остальных, чтобы рисовать метки.

## Авторизация

Игровой клиент ходит в API с заголовком:

```
Authorization: Bearer <launch-token>
```

Токен живёт **5 минут**. Его можно обновлять двумя способами:

- `POST /api/launch-token` с тем же заголовком `Authorization: Bearer <старый токен>`
  — вернёт новый токен без пароля (так делает мод);
- повторный вход через лаунчер или `/api/party/token` с логином и паролем.

Если пришёл `401` — обновите токен и повторите запрос. Если `403` — нет подписки
или аккаунт заблокирован.

### Вариант 1 — через лаунчер (рекомендуется)

1. Лаунчер вызывает:

   `POST /api/launcher-auth`

   ```json
   {
     "username": "nick",
     "password": "пароль",
     "hwid": "HWID-ПК"
   }
   ```

   Проверяются пароль, бан, подписка и HWID. В ответе кроме данных пользователя
   приходит готовый токен:

   ```json
   {
     "success": true,
     "uid": 73,
     "username": "nick",
     "launch_token": "<launch-token>",
     "expires_in": 300
   }
   ```

2. Лаунчер запускает игру и передаёт токен моду. Удобные способы:
   - JVM-аргумент: `-Dstellar.token=<token>`;
   - переменная окружения: `STELLAR_TOKEN=<token>`;
   - файл рядом с игрой (если так проще вашему лаунчеру).

3. Мод раз в 4 минуты вызывает `POST /api/launch-token` с
   `Authorization: Bearer <текущий токен>` и заменяет токен на новый.
   Пароль моду не нужен.

### Вариант 2 — мод без лаунчера

Мод может войти сам:

`POST /api/party/token`

```json
{
  "username": "nick",
  "password": "пароль",
  "hwid": "опционально"
}
```

Ответ:

```json
{
  "ok": true,
  "token": "<launch-token>",
  "user_id": 73,
  "username": "nick",
  "expires_in": 300
}
```

Проверяется пароль, бан, активная подписка и HWID. Токен обновляется тем же
запросом раз в 4 минуты. Пароль держите только в памяти, не пишите в конфиг.

### Вариант 3 — cookie сайта

Если клиент умеет использовать cookie, подойдёт `stellar_session`.
Для мода это неудобно, поэтому основной путь — Bearer-токен.

Во всех запросах ниже подразумевается авторизация.

## Состояние пати

`GET /api/party`

```json
{
  "ok": true,
  "party": {
    "id": 12,
    "leader_id": 73,
    "created_at": "2026-11-05T10:00:00.000Z",
    "members": [
      {
        "user_id": 73,
        "username": "nick",
        "avatar_url": null,
        "nickname_color": "#a78bfa",
        "online": true,
        "in_game": true,
        "joined_at": "2026-11-05T10:00:00.000Z",
        "is_leader": true,
        "is_self": true
      }
    ]
  },
  "invites": [],
  "max_members": 8,
  "position_ttl_seconds": 10,
  "realtime": {
    "url": "https://<project>.supabase.co",
    "ws_url": "wss://<project>.supabase.co/realtime/v1/websocket?apikey=...&vsn=1.0.0",
    "anon_key": "<public anon key>",
    "channel": "party_12_<secret>",
    "position_hz": 8

```

Если пользователь не в пати, `party` = `null`, а `invites` содержит входящие приглашения.
Поле `realtime` = `null`, если сервер не настроен (`SUPABASE_ANON_KEY` не задан).

## Realtime-канал (рекомендуется, задержка ~50–150 мс)

Этот способ нужен для «почти моментальных» меток. Клиент подключается напрямую
к Supabase Realtime по WebSocket и обменивается позициями через Broadcast.
Сайт в передаче позиций не участвует, поэтому задержка минимальна, а Vercel
не тратит запросы.

`GET /api/party` для участника возвращает блок `realtime` (см. выше). Если он `null`,
используйте HTTP-фолбэк из следующего раздела.

### 1. Подключение

Откройте WebSocket:

```
wss://<project>.supabase.co/realtime/v1/websocket?apikey=<anon_key>&vsn=1.0.0
```

### 2. Вход в канал

Отправьте:

```json
{
  "topic": "realtime:party_12_<secret>",
  "event": "phx_join",
  "payload": {
    "config": {
      "broadcast": { "self": false }
    }
  },
  "ref": "1"
}
```

Дождитесь ответа с `"event": "phx_reply"` и `"status": "ok"`.

### 3. Отправка своей позиции

5–10 раз в секунду (рекомендуется 8 Гц):

```json
{
  "topic": "realtime:party_12_<secret>",
  "event": "broadcast",
  "payload": {
    "type": "broadcast",
    "event": "position",
    "payload": {
      "user_id": 73,
      "username": "nick",
      "server": "play.example.com",
      "dimension": "minecraft:overworld",
      "x": 128.5,
      "y": 64.0,
      "z": -302.25,
      "yaw": 90.0,
      "health": 20,
      "t": 1762345678901
    }
  },
  "ref": "2"
}
```

`t` — время отправки в миллисекундах (Unix epoch). По нему клиент отбрасывает
устаревшие позиции.

### 4. Приём чужих позиций

Сервер присылает:

```json
{
  "topic": "realtime:party_12_<secret>",
  "event": "broadcast",
  "payload": {
    "type": "broadcast",
    "event": "position",
    "payload": {
      "user_id": 74,
      "username": "friend",
      "server": "play.example.com",
      "dimension": "minecraft:overworld",
      "x": 100.0,
      "y": 64.0,
      "z": -280.0,
      "yaw": 45.0,
      "health": 18,
      "t": 1762345678800
    }
  },
  "ref": null
}
```

Игнорируйте сообщения, где `payload.event !== "position"` или `payload.payload.user_id`
совпадает с вашим.

### 5. Heartbeat

Каждые 25–30 секунд:

```json
{ "topic": "phoenix", "event": "heartbeat", "payload": {}, "ref": "3" }
```

### 6. Переподключение и смена ключа

- При обрыве WebSocket переподключайтесь с экспоненциальной задержкой (1–5 с).
- После `kick`/`leave` другого участника ключ канала меняется. Периодически
  (раз в 5–10 секунд) запрашивайте `GET /api/party`; если `realtime.channel`
  изменился — переподключитесь к новому каналу.
- Если пришёл `phx_error` или канал не отвечает — перезайдите в канал.

### 7. Выход из мира

Просто перестаньте отправлять позиции и отправьте HTTP `DELETE /api/party/positions`.
Остальные перестанут рисовать метку после TTL (10 секунд). Можно дополнительно
отправить broadcast `{ "event": "leave", "payload": {} }`.

### 8. Надёжность

Рекомендуется параллельно отправлять позицию в HTTP `POST /api/party/positions`
раз в 1–2 секунды. Это:
- держит актуальными HTTP-фолбэк и страницу `/dashboard/party`;
- позволяет другим клиентам продолжить видеть метки, если WebSocket оборвался.

Realtime остаётся основным каналом для мгновенных меток, HTTP — страховкой.

## Действия

`POST /api/party` с телом:

| action | body | Описание |
| --- | --- | --- |
| `create` | — | Создать пати (пользователь становится лидером). |
| `invite` | `{ "username": "friend" }` | Пригласить друга. Только лидер. |
| `accept` | `{ "invite_id": 5 }` | Принять приглашение. |
| `decline` | `{ "invite_id": 5 }` | Отклонить приглашение. |
| `leave` | — | Покинуть пати. Лидер передаётся следующему участнику. |
| `kick` | `{ "user_id": 74 }` | Исключить участника. Только лидер. |
| `disband` | — | Распустить пати. Только лидер. |

Ответ — актуальное состояние пати в том же формате, что и `GET /api/party`.

Ошибки: `400` неверные данные, `401` нет авторизации, `403` нет прав / не друг,
`404` не найдено, `409` конфликт (уже в пати, нет мест, приглашение уже отправлено).

## Синхронизация позиции (HTTP-фолбэк)

`POST /api/party/positions`

```json
{
  "server": "play.stellar-client.xyz",
  "dimension": "minecraft:overworld",
  "x": 128.5,
  "y": 64.0,
  "z": -302.25,
  "yaw": 90.0,
  "health": 20
}
```

- `server` — адрес сервера, на котором играет пользователь (до 120 символов).
- `dimension` — ключ измерения (`minecraft:overworld`, `minecraft:nether`, `minecraft:the_end`).
- `x/y/z` — обязательны, конечные числа в диапазоне ±30 000 000.
- `yaw` — от -720 до 720, необязательно.
- `health` — 0–20, необязательно.

Отправляйте не чаще **1 раза в секунду** (лимит — 120 запросов в минуту).

`GET /api/party/positions`

```json
{
  "ok": true,
  "ttl_seconds": 10,
  "positions": [
    {
      "user_id": 74,
      "username": "friend",
      "nickname_color": "#67e8f9",
      "server": "play.stellar-client.xyz",
      "dimension": "minecraft:overworld",
      "x": 100.0,
      "y": 64.0,
      "z": -280.0,
      "yaw": 45.0,
      "health": 18,
      "updated_at": "2026-11-05T10:01:02.000Z",
      "age_ms": 1200
    }
  ]
}
```

Позиции старше 10 секунд не возвращаются. Если участник вышел из игры — перестаньте
рисовать его метку после `ttl_seconds`.

`DELETE /api/party/positions` — удалить свою позицию (вызывайте при выходе из игры).

## Логика меток в клиенте

1. Если `GET /api/party` вернул `realtime`, подключитесь к WebSocket-каналу и
   получайте позиции из broadcast-событий `position`.
2. Если `realtime` = `null` или WebSocket недоступен — резервный вариант:
   `GET /api/party/positions` раз в 1 секунду.
3. Свою позицию берите из локального игрока (`mc.player`), не из ответа.
4. Храните последнюю позицию каждого `user_id` с временем `t` (или временем приёма).
   Позиции старше 5–10 секунд не рисуйте.
5. Метку рисуйте только если:
   - `position.server === ownServer`, и
   - `position.dimension === ownDimension`.
6. Если сервер/измерение не совпадают — покажите в HUD «другой сервер» / «другое измерение»,
   но не рисуйте метку в мире.
7. Цвет метки берите из `nickname_color`, иначе — фиксированный цвет пати.
8. Рядом с меткой показывайте ник и расстояние:
   `distance = sqrt((x2-x1)^2 + (y2-y1)^2 + (z2-z1)^2)`.
9. Для плавности интерполируйте позицию между broadcast-сообщениями: при 8 Гц
   метка движется плавно, даже если рендер идёт 60 раз в секунду.
10. При выходе из мира/смерти/дисконнекте перестаньте отправлять позиции и вызовите
    `DELETE /api/party/positions`.
11. Раз в 5–10 секунд обновляйте `GET /api/party`: после kick/leave ключ канала
    меняется, и клиенту нужно переподключиться к новому `realtime.channel`.
12. Если пришёл `phx_error` или WebSocket закрылся — переподключитесь и заново
    войдите в канал (`phx_join`).

## Рекомендуемый HUD

- список участников пати с онлайн-статусом;
- у лидера — кнопки «пригласить» и «исключить»;
- переключатель меток (hotkey);
- отображение сервера/измерения и предупреждение, если участники не рядом.

## Приватность и ограничения

- Координаты доступны только участникам пати: HTTP-позиции фильтруются по `party_id`,
  а Realtime-канал имеет случайное имя и выдаётся только участникам.
- При выходе/исключении участника ключ Realtime-канала меняется.
- При использовании Realtime позиции не пишутся в БД и не хранят историю.
- Приглашать можно только друзей; максимум 8 участников.
- На публичных серверах ESP/метки могут нарушать правила сервера. Используйте на своих
  серверах или там, где это разрешено.

## Настройка сервера

Для Realtime нужен публичный anon key Supabase. Добавьте в переменные окружения
(локально `.env.local`, в проде — Vercel → Settings → Environment Variables):

```
SUPABASE_ANON_KEY=<anon public key>
```

URL проекта определяется из `DATABASE_URL` автоматически. Если нужно явно:

```
SUPABASE_URL=https://<project>.supabase.co
```

Без `SUPABASE_ANON_KEY` API вернёт `realtime: null`, и клиент будет использовать
HTTP-фолбэк.
